# Retention Canvas — Спецификация JSON-схемы & Руководство для AI (ChatGPT / Claude)

Данный документ описывает структуру данных, схему JSON и правила генерации для интерактивного стратегического графа **Retention Canvas**.

Используйте эту спецификацию, чтобы передавать её в любые LLM (ChatGPT-4o, Claude 3.5 Sonnet, Google Gemini Pro) вместе с фотографией наброска схемы на листе бумаги А4, ментальной карты или блок-схемы. Нейросеть сгенерирует точный JSON, который можно сразу импортировать в интерфейс Canvas в один клик.

---

## 1. Экспресс-инструкция: от листка А4 к интерактивной веб-схеме

1. **Нарисуйте схему** на бумаге А4 (блоки, стрелки, подписи, метрики, ключевые циклы).
2. **Сделайте фото** или скриншот.
3. **Откройте ChatGPT** (рекомендуется GPT-4o) или **Claude 3.5 Sonnet**.
4. **Прикрепите фото** и вставьте готовый системный промпт из файла [`PROMPT_FOR_CHATGPT.md`](./PROMPT_FOR_CHATGPT.md).
5. **Скопируйте полученный JSON** из ответа нейросети.
6. В веб-приложении нажмите **«Импорт JSON»** (в навбаре, личном кабинете или по клавише `⌘I`), вставьте код и нажмите **«Импортировать проект»**.
7. Ваша схема моментально развернется в интерактивном графе с зумом, перетаскиванием, связями и сохранением в вашем личном кабинете!

## 2. Архитектура JSON-документа

Корневой объект проекта:

```typescript
interface CanvasProjectJson {
  title: string;          // Название схемы / воронки
  description?: string;    // Краткое описание гипотезы или цепочки шагов
  layoutMode?: 'freeform' | 'pyramid' | 'flywheel'; // По умолчанию 'freeform'
  theme?: 'dark' | 'stone' | 'slate' | 'graphite' | 'monochrome' | 'light' | 'sand' | 'mist'; // По умолчанию 'dark'
  nodes: (StrategyNode | ImageNode | TextNode)[];   // Массив карточек (стратегия, текст, фото)
  edges: StrategyEdge[];   // Массив связей (стрелок)
  drawings?: DrawingStroke[]; // Массив рисунков от руки (если есть)
}
```

## 3. Спецификация элементов холста (Nodes)

Холст поддерживает **3 типа элементов**, позволяющих создавать полноценные объяснительные воркфлоу, иллюстрированные архитектуры и схемы любой сложности:

### 3.1. Стратегическая карточка (`type: "strategyNode"` или без `type`)
Основная карточка этапа воронки с метриками, категорией и статусом:

```json
{
  "id": "step_beacon",
  "type": "strategyNode",
  "position": { "x": 520, "y": 380 },
  "data": {
    "title": "HARDWARE СИГНАЛИЗАТОР",
    "badge": "Шаг 2 • Маяк",
    "category": "hardware",
    "description": "Физический маяк с датчиком присутствия, выдаваемый резидентам клуба.",
    "keyMetric": "Заказ маяка: 42% когорты",
    "outcome": "Физическая привязка к бренду",
    "imageUrl": "https://images.unsplash.com/photo-1508614589041-895b88991e3e?w=600",
    "tags": ["Hardware", "Beacon", "Physical"]
  }
}
```

### 3.2. Объяснительный текстовый блок (`type: "textNode"`)
Отдельный независимый блок с текстом, заметкой, гипотезой, комментарием команды или выводом. Перемещается по холсту как обычная карточка:

```json
{
  "id": "note_hypo_beacon",
  "type": "textNode",
  "position": { "x": 520, "y": 680 },
  "data": {
    "title": "💡 Продуктовая гипотеза #2",
    "text": "Физический маяк снижает 30-дневный отток на 60%, так как овеществляет статус членства на рабочем столе пользователя.",
    "color": "amber",
    "fontSize": "md",
    "width": 340
  }
}
```

**Цветовые палитры для `textNode` (`color`)**:
- `"default"` (нейтральный темный/светлый)
- `"amber"` (янтарный / гипотезы и внимание)
- `"emerald"` (изумрудный / выводы и позитивные метрики)
- `"blue"` (синий / системные пояснения и инструкции)
- `"rose"` (коралловый / риски и точки оттока)
- `"purple"` (фиолетовый / инсайты и психология)
- `"graphite"` (минималистичный графит)

### 3.3. Фото-карточка / Макет экрана (`type: "imageNode"`)
Отдельная визуальная карточка с изображением, макетом интерфейса или фотографией скетча на бумаге А4:

```json
{
  "id": "img_mockup_beacon",
  "type": "imageNode",
  "position": { "x": 520, "y": 80 },
  "data": {
    "imageUrl": "https://images.unsplash.com/photo-1518770660439-4636190af475?w=600",
    "title": "Рендер маяка V1",
    "caption": "Индикатор Bluetooth Low Energy в матовом алюминии",
    "width": 340
  }
}
```

## 4. Категории карточек (`category`) и их назначение

В Retention Canvas встроена фирменная дизайн-система из 8 смысловых категорий:

| Категория (`category`) | Цвет в интерфейсе | Назначение | Рекомендуемый бейдж |
|---|---|---|---|
| `foundation` | 🔷 Неоновый голубой (`#38BDF8`) | Фундаментальная стратегия, бизнес-модель, точка старта | `Paradigm Shift`, `Foundation`, `Step 1` |
| `psychology` | 🟣 Фиолетовый (`#C084FC`) | Эмоции, статус клиента, самооценка, психологическая ценность | `Value Delivery`, `Psychology`, `Status` |
| `hardware` | 🟡 Янтарный (`#FBBF24`) | Аппаратные решения, физические триггеры, маяки, аксессуары | `Retention Tool`, `Hardware`, `Beacon` |
| `retention` | 🟢 Изумрудный (`#34D399`) | Механики возврата, формирование привычки, циклы удержания | `Habit Loop`, `Retention`, `Re-engagement` |
| `event` | 🔵 Насыщенный синий (`#60A5FA`) | Мероприятия, ивенты, комьюнити, офлайн-встречи | `Event Architecture`, `Community`, `Offline` |
| `lifecycle` | 🔴 Кораллово-розовый (`#FB7185`) | Жизненный цикл клиента, предотвращение оттока, реактивация | `Relevance Engine`, `Anti-Churn`, `Lifecycle` |
| `outcome` | 🟡 Золотой (`#FACC15`) | Конечная стратегическая цель, ключевой результат всей воронки | `Strategic Outcome`, `End Result`, `Apex` |
| `custom` | ⚪ Матовый графитовый (`#94A3B8`) | Произвольный шаг, интеграция, техническая задача | `Custom Block`, `Technical`, `Service` |

## 5. Спецификация связей (Edges)

Связи показывают логические переходы, циклы и зависимости между карточками:

```json
{
  "id": "e_step1_to_step2",
  "source": "step_1",
  "target": "step_2",
  "label": "Конверсия 68%",
  "animated": true,
  "styleType": "bezier",
  "imageUrl": "https://example.com/icon.png"
}
```

## 6. Геометрические стандарты расстановки и объяснительных воркфлоу

Чтобы воркфлоу читался легко и последовательно, как в профессиональных дизайн-системах, используйте математические отступы:

- **Ширина карточки по умолчанию**: **340-360 px**
- **Горизонтальный шаг между шагами воронки**: **`dx = 440 px`**
  - Оставляет между карточками идеальный промежуток в **100 px** для размещения подписей на стрелках (`label`) и плавных изгибов кривых Безье.
  - Колонка 0: `x = 80`
  - Колонка 1: `x = 520`
  - Колонка 2: `x = 960`
  - Колонка 3: `x = 1400`
- **Вертикальный шаг между ветками / дорожками**: **`dy = 280-320 px`**

### Парадигма 3 параллельных дорожек (`horizontal_tracks`):
Для создания богатого объяснительного воркфлоу разделите пространство холста на 3 дорожки по вертикали:
1. **Верхняя дорожка (`y = 80`)**: Фотографии, мокапы и скетчи (`imageNode`).
2. **Центральная дорожка (`y = 380`)**: Скелет продуктовой стратегии (`strategyNode`).
3. **Нижняя дорожка (`y = 680`)**: Текстовые пояснения, гипотезы и расчеты (`textNode`).

Карточки на одном шаге имеют одинаковую координату `x`, образуя стройную вертикальную ось контекста (Фото ➔ Стратегия ➔ Обоснование).

> **Совет:** Вы также можете использовать инструмент MCP `build_explanatory_workflow` или `auto_layout_project`, чтобы рассчитать и расставить карточки автоматически в 1 клик.

## 8. Как парсер обрабатывает упрощенный JSON от нейросетей

Если нейросеть пришлет упрощенный вариант:
- Автоматически удаляются обрамляющие блоки markdown (```` ```json ````).
- Если данные карточки указаны не в `data: {}`, а на верхнем уровне (`{ "id": "1", "title": "...", "description": "..." }`), парсер сам бережно упакует их в `data`.
- Если поле `category` указано произвольным словом («психология», «девайс», «шаг»), парсер сопоставит его с правильной встроенной категорией.
- Если координаты `position` отсутствуют, парсер запустит топологический алгоритм и автоматически разложит граф слева направо.
- Если связи указаны через `"from"` и `"to"`, парсер поймет их как `"source"` и `"target"`.
